# Local Protocols native QA

Use a simulator dedicated to this task and the current local working tree. This setup does not deploy anything or use an application auth bypass. All fixtures belong to a temporary Supabase project. Do not overlap this harness with the isolated security or mobile HTTP runners, which use the same 554xx ports.

1. From `nouri-api`, with Node 22 on PATH, run `node --experimental-strip-types scripts/start-protocols-native-qa.ts` in an interactive terminal. Keep it running. It prints the private temporary directory containing `fixture.json` and `metro.log`; do not commit those files. The account signs in through ordinary Supabase password authentication. API fixtures populate normal diary and weight data; Protocol tracking starts off. Metro uses `CI=0` so it watches source changes; after an edit, verify and reload the production-mode bundle before attributing a native result to that source revision.
2. Build `ios/Nouri.xcworkspace`, scheme `Nouri`, Debug for an iOS Simulator, using a temporary derived-data path and ad-hoc signing (`CODE_SIGNING_ALLOWED=YES CODE_SIGN_IDENTITY=-`). The initial unsigned build failed SecureStore reads; the signed simulator build successfully signed in. No app entitlement or signing-project setting was changed.
3. Install the resulting `Nouri.app` on that isolated simulator with `xcrun simctl install <udid> <app-path>`.
4. Inspect the served bundle **before launching it**. Request `http://127.0.0.1:8084/.expo/.virtual-metro-entry.bundle?platform=ios&dev=false&minify=true`. Verify both `http://127.0.0.1:4199` and `http://127.0.0.1:55421`, and absence of the hosted endpoint values and `expo/virtual/env` import. Keep the bundle local.
5. Launch explicitly:

   ```sh
   xcrun simctl launch <udid> com.dribsnis.app \
     -RCT_jsLocation 127.0.0.1:8084 \
     -RCT_enableDev NO -RCT_enableMinification YES
   ```

6. Run the [native login flow](../../test/manual/native/protocols-login.yaml) with local Maestro, supplying `QA_EMAIL` and `QA_PASSWORD` from the private fixture through explicit `-e` test parameters. Bare process variables with those names are not automatically flow parameters. Set `MAESTRO_CLI_NO_ANALYTICS=1` and `MAESTRO_CLI_ANALYSIS_NOTIFICATION_DISABLED=true`; keep output/debug artifacts local. Continue with [settings navigation](../../test/manual/native/protocols-shell.yaml) and [opt-in/root sections](../../test/manual/native/protocols-opt-in.yaml). The combined [sign-in/root/reminder flow](../../test/manual/native/protocols-onboarding-reminder.yaml) composes these checks and reminder CRUD; [reminder cancellation](../../test/manual/native/protocols-reminder-cancel.yaml) exercises unsaved page navigation. Flows have explicit starting-state requirements; do not run destructive later flows against a real account. See [acceptance evidence](protocols-v1.md) for actual outcomes and the full remaining matrix.
7. Enter `q` in the harness terminal. Its terminal completion verifies Metro/API shutdown and removal of its temporary Supabase project. Shut down the task's simulator when finished. Existing development services and simulators are not selected or reset.

The inspected Expo SDK 54 development transform imports a generated `.env` module even when the process has `EXPO_NO_DOTENV=1` and explicit loopback variables. Clearing Metro's transform cache did not remove the hosted values in that module. The production-mode transform correctly inlines the harness environment. Initial native attempts received invalid-credential responses from the old hosted Auth endpoint; no authenticated hosted application writes occurred. Do not count those attempts as local validation. The subsequent verified production-mode bundle signed in to the isolated local account.

Maestro 2.10's multi-argument launch produced `-RCT_jsLocation … RCT_enableDev false RCT_enableMinification true`: the later iOS keys lacked a leading dash. The [official launch-argument feature](https://docs.maestro.dev/api-reference/commands/launchapp) therefore did not select production mode in this observed run. The explicit `simctl` launch above was verified and the login flow deliberately does not relaunch the app. The app's existing `RCTBundleURLProvider` reads these normal development settings; no test flag or alternate authentication path was introduced into the app.

Current verified device: isolated iPhone 17e, iOS 26.5, `9F5E1AB1-FFDE-4CD3-8F12-5AC28CF831CA`. Native build artifacts are in `/private/tmp/nouri-protocol-native`; Maestro 2.10 was unpacked to `/private/tmp/nouri-maestro-cli`, without changing package manifests or shell profiles. Paths and test-account credentials are disposable; recreate the setup rather than depending on them permanently.

### Android local bundle and sign-in

A separate task emulator `Nouri_Protocols_QA` uses serial `emulator-5556`; the existing `emulator-5554` was left untouched. Its temporary AVD lives under `/private/tmp/nouri-protocols-avd-2hfzr_2u`. Install the existing local debug APK with an explicitly selected serial. The installed React Native development settings read `debug_http_host`, `js_dev_mode_debug` and `js_minify_debug` from the app's default shared preferences. On this disposable debug installation, `run-as com.dribsnis.app` configured the loopback Metro host and production-mode transform; no app/native project source setting was changed. Inspect the served Android bundle and its API/Auth endpoints before launching, as on iOS. Use `adb -s <qa-serial> reverse` for the selected Metro, API and Auth ports.

The current supplemental Metro/API processes use ports 8085/4200 with the retained disposable Auth/DB at 55421/55422; the original 8084/4199 harness remains separate. Both were confirmed live before continuing. The newer API watches source; an already loaded production-mode mobile bundle needs an explicit verified reload after edits. The supplemental process may be stopped independently without removing the retained Supabase fixture. Do not clean up that project as a substitute for the approval-blocked native deletion test.

Maestro's Android email entry stopped before completing the text. After confirming that process had exited, normal `adb shell input` events filled the visible email/password controls from private fixture values and tapped Sign in. Keep credentials out of command output and stored repository scripts. Screenshot/hierarchy verification showed authenticated Food Diary. That initial result proved sign-in only; subsequent scoped Android Protocol passes are recorded in the acceptance evidence. Any native action must select this QA serial and use current hierarchy bounds rather than copied iOS wheel/tap selectors.

The [Android pagination walkthrough](../../test/manual/native/protocols-android-pagination.yaml) uses the separate 33-course pagination account and performs no stored-record mutations. It verifies loading the second page, selecting its historical course, and retaining Levels selection across focus refresh. It requires its documented fixture dates; the 60-second bounded scroll limit accommodates the first 30-card page. Inspect native checkbox roles separately from the visual flow. It has passed on Android 16/API 36; do not infer other platforms or the full accessibility matrix from it.

For reversible compact/large-text QA, record `wm size`, `wm density` and `settings get system font_scale` first. The observed device used 1080×2424 at 420 dpi, font scale 1.0. A temporary 945×1680 override gives 360×640 dp at that density; font scale 1.5 was checked. The September 22 fix requires a rebuilt Android binary containing `plugins/withFontScale.cjs`; an OTA/Metro reload alone cannot install the native Activity/Fabric changes. On that build, test warm 1.0 → 2.0 → 1.0 transitions without restarting, including a retained draft, then restore the recorded settings. Older binaries required a restart and are not evidence for the fix. iOS shared text refreshes only its native paragraph during Dynamic Type changes. See [dated native hardening evidence](protocols-v1-2026-09-22.md) for verified scope and physical screen-reader limitations.

An API-only outage can be reviewed non-destructively by removing the selected emulator's `tcp:4200` reverse mapping while retaining Auth `55421` and Metro `8085`. Restore it before using the visible retry action. This does not stop/reset the API, Supabase or database, and does not authorize running either pending destructive check. Record the observed error and successful authenticated recovery; do not call a mere port change a passed outage scenario.

The [Today rollover flow](../../test/manual/native/protocols-today-rollover.yaml)
checks the Home entry path after a foreground calendar-date change. Enter using
Home's Open Protocols Today control, background the dedicated emulator, change
only its timezone to one on the next date, then foreground without restarting or
tapping Today. Supply `QA_NEW_DATE` and `QA_NEW_ZONE`. On Android the authorized
QA command is `adb -s <qa-serial> shell cmd alarm set-timezone <zone>`; record and
restore the original zone. Do not change the server/device clock. Separately
select a historical day and confirm it stays fixed across a zone change. Route
date `null` means following today; a date string means an explicit selection.
